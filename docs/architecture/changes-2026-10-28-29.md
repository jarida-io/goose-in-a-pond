## Architecture

### Long tasks and agents (#694)

- **Tasks.** A task, its plan's steps and their artifacts live in `pond_system.db` (migration 0062).
- **Running.** The prime starts a task with `task_start`. The inference lane runs it one helper at a
  time: a planner, the workers its plan names, and a verifier.
- **Inputs and outputs.** Helpers read and write artifacts through `giap-task-work`, and a step
  hands back a fixed outcome.
- **Agents as recipes.** An agent is an `agent_recipes` row whose `giap_role` block has examples,
  activations, before and after hooks, and `a2a.expose`.
- **Prefills.** Every agent's preamble is compiled into its own KV snapshot, one per prompt shape,
  and rebuilt when its recipe changes.

### Deep research (#699, #701)

- **Starting it.** The + menu on the desktop and the phone sends a turn with `deep_research`. The
  pond starts a `research` task itself (migration 0067). It doesn't wait for the model to call
  `task_start`, and it opens the stream with the same call the prime would make.
- **Reports.** The planner gathers, gives each section a step, then writes the summary.
  `research_report::assemble` joins them in plan order, so a report is as long as its plan.
- **Plans.** The shipped composer role writes itineraries, meal plans and lists. Dated events go to
  a Calendar artifact.
- **Export.** `GET /long-tasks/{id}/export` gives Markdown, a standalone web page, or an iCalendar
  file.
- **Names.** The helpers are shown as Point Gander, Forager Gosling, Sentinel Goose and Nestmaker
  Goose. Their ids are unchanged.

### The line (#703)

- **Order.** One slot runs every open task, so `long_task_queue::run_order` defines the order: the
  order tasks were asked for. The runner, every task's view (`queue: {position, of, ahead}`),
  `GET /long-tasks/queue` and the prime's note all read it.
- **What it replaced.** The runner used to pick by `updated_at`, meant to let tasks take turns. A
  step never touches `updated_at`, so the oldest task always won.

### Pace and reliability (#706)

| Change | Why |
|---|---|
| A member's long task goes before the pond's chores; only a compaction outranks it, and a chore that has waited 15 minutes gets one turn | The lane picked the longest-waiting job, so a long task lost almost every gap between steps |
| The lane counts a held subagent permit as a turn in flight | A background subagent outlived its turn, and chores started beside it |
| A run that moved a task on is followed at once | The runner waited for its 30 s poll after every run |
| Inputs up to 1,500 tokens each, 3,000 in all, go in a step's brief | A worker spent its first turn reading them |
| A helper that runs out of turns fails its first try, and the retry gets half again as many turns plus what it saved | Half-done work counted as done |
| A completed report with nothing saved and a summary under 20 characters fails as empty | It counted as done |
| The runner ends a helper's run when it reports, and keeps the report | The model's turn after "stop here" cost a full round of reasoning |
| A result saved as "Arusha Trip Result" is still the result | Two of eight finished tasks read as having no result |
| `check_task` answers for a long task's id | Every call on the Orin was refused |
| Every settled step is traced with its attempt, turns, inlined inputs and failure | A retry's reason was lost once it succeeded |

**Kept on purpose:**
- Helpers keep thinking on (Jerry, 2026-10-29).
- The quiet before a task starts was kept at 30 s here, then cut to 10 s in #718, which re-checks
  when the quiet is due. A step the household interrupts reruns without spending a try.

### The inference engine (#697, #702, Goose#21, Goose#22)

- **Boot.** Goose's recovery compaction no longer runs inside boot's first prefill compile. A prompt
  is now admitted by its window alone, and nothing else may reach the engine under the compile
  scope.
- **The MTP drafter.**
  - **Attaching.** It attaches when the registry names it after the model has loaded. It used to be
    decided once, at load, and the pond names it from a background task at boot.
  - **Reporting.** Each turn reports its drafts. The llama.cpp paths reported `draft: None`, so
    `drafter=false` in `turn_end` meant nothing.
  - **Settings that used to fail every turn:** `draft_n_max: 0` (now the way to turn speculation
    off), `draft_p_min` above 0, and a verify batch with no cache slot.
  - **Depth.** The pond sets draft depth 2 when it attaches the drafter, unless the household set
    one (#706).
- **Measured on the Orin** (E4B QAT, 9K-token prompt, temperature 0.8):

  | Setting | Decode |
  |---|---|
  | No drafting | 22.6 tok/s |
  | Draft depth 4 | about 28.5 tok/s |
  | Draft depth 2 | about 31 tok/s |

- **macOS build.** `pond-adapters-goose` builds on macOS again (E0275, from a set's type inferred
  through objc2; #703).

### Pond administration (#705, #708)

- **Routes.** `/api/v1/admin/*` gives a member's phone the pond's stats, its files and caches, its
  tasks and artifacts, its health, and its power modes. It's served by a host adapter for the
  machine it runs on.
- **Unlocking.** The admin card unlocks it, as described under security below.
- **The service account.** `scripts/install.sh` offers a new pond its own locked system account,
  `agamemnon`, and `giap.sh service-account` moves an existing pond to it or back. Its sound comes
  from a lingering user manager for `agamemnon`, so its PulseAudio starts at boot.

### Web search (#692)

- **One tool.** `search_web(question)` stays the model's one tool. Behind it the pond asks Brave's
  LLM Context and ranks the extracted text to the existing budget.
- **Fallback.** A key or quota error says so. Any other failure falls back to a search plus
  reading three pages.
- **Nearby places** are opt-in and come back from the same call.

## Security and privacy

| Control | What it does | Where it's enforced |
|---|---|---|
| **The admin card** | 80 random bits, printed once as `XXXX-XXXX-XXXX-XXXX`. The pond keeps only a PBKDF2-HMAC-SHA256 verifier (600,000 rounds) in `setup/admin.json` (`0600`, never in `Settings` or the database). The plaintext is sealed to the board's TPM, so only root on that board can print it again. Rotating it locks every device unlocked with the old card | `pond-server admin-card`, `giap.sh admin-card` |
| **Unlocking** | Only a member's phone sees My Pond, never a guest's. An unlock covers one device for 15 minutes from its last admin request. Every other admin route answers `403 admin_locked`. Wrong cards: five free tries, then one per 30 s, doubling to one per 10 minutes, across all clients. Each unlock, refusal and destructive action is an audit event, and the other members' phones are told | `pond-api` admin routes |
| **Remote unlock** | Allowed over the household LAN, and over remote access only from the device's enrolled tailnet machine | the auth middleware |
| **Files** | Paths stay inside the data directory: `..`, absolute paths and symlinks out are refused. `setup/`, `tls/`, `secrets/`, `secrets.json`, `embedded-network/` and the `.runtime_*` files are never listed. Live databases and model stores can't be deleted. Build output is never in scope | admin files routes |
| **Power** | A sudoers drop-in lets the service run only `nvpmodel -m [0-9]` and `systemctl reboot`, and it is installed only after `visudo -c` accepts it. The phone confirms every mode change and restart | `/etc/sudoers.d/goose-in-a-pond-power` |
| **`agamemnon`** | A locked system account with no password and no shell, `nologin`. Its data is under `/var/lib/goose-in-a-pond` (`0750`). The login keeps read access through an ACL that keeps each file's own mask, so what the pond made private stays private. Undo restores the old unit byte for byte | `scripts/install-systemd.sh` |
| **Another member's tasks** | Only a place in the line (`another_member`), never its goal: in task views, `GET /long-tasks/queue`, the prime's waiting note, the card, and the admin task list | `long_task_queue::reaches`, admin routes |
| **Who owns a task** | A deep-research task belongs to the member asking. Nobody identified gets 403, before anything is saved. `check_task`'s long-task answer is scoped to the caller, and another member's id reads the same as an unknown one | `pond-api`, `pond-mcp-server` |
| **What leaves the house** | Research and plan steps never put a person's name, health or diet in a web search. Nearby places send the town only, never coordinates, and only when the household turns them on. Brave's text is transient: after the turn, history keeps only a stub naming the source domains | role recipes, `giap-knowledge` |
| **Exports** | The exported web page escapes all markup the model wrote, links only to web and mail addresses, and fetches nothing when opened. CORS exposes `Content-Disposition` for the file name | `report_export`, the CORS layer |

## Open

- **The nano.** It runs `feat/my-pond` until the admin card is made, then goes back to `main`. Its
  move to `agamemnon` waits for Jerry.
- **Shells and tools still assume a user unit:** the desktop shell and kiosk on the same board, and
  the dev tools (`jetson.sh deploy`, `jetson-remote.sh`, `console-collect.sh`).
- **Long tasks:**
  - The prime can't restart a task that has failed, because failed is final.
  - A delegated subagent can't be resumed with more turns.
  - Saving and reporting in one call, the nudge, household reads and lenient plans are in
    PAI-6 §8.12 (#717), with `SNAPSHOT_MAX_TOKENS` raised in Goose#23.
  - A web answer can still carry a wrong number from a search snippet. On the Orin, one run gave
    the SGR as 1 h 26 min, and the next run got it right. Only a step with an acceptance check is
    verified.
  - A report still takes 10 to 12 minutes on the Orin, mostly in its sections, at about a minute
    a step.
- **Trace noise:** the prefix tracker logs two invalidations per helper run, though the engine
  restores that run's preamble from its snapshot.
- **Not checked on a phone:** the phone's queue card (#204) and My Pond screens (#205).
- **CI:** the advisory scans and two `hub-visual-verify` Playwright tests fail on `main`, and a
  `device_budget` test is flaky when the suite runs in parallel.
